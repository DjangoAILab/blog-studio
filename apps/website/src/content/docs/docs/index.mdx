## Start with the job, not the stack

<CardGrid>
  <Card title="Write" icon="pencil">
    Open an existing Markdown document, work in visual or source mode, and get
    an acknowledged draft without waiting for Git or a deployment.
  </Card>
  <Card title="Preview" icon="open-book">
    Run the real generator and theme. Preview correctness comes from your site,
    not from a second renderer that drifts over time.
  </Card>
  <Card title="Release" icon="rocket">
    Inspect the manifest diff, publish immutable assets before pages, refresh
    cache paths, and verify a public release marker.
  </Card>
  <Card title="Recover" icon="setting">
    Keep exact manifests and structured events so retries, cancellation, restart
    recovery, and rollback are explicit operations.
  </Card>
</CardGrid>

## Choose a path

- **I want to install it:** follow [Self-hosting](/docs/guides/self-hosting/),
  then [configure a workspace](/docs/configuration/workspaces/).
- **I have a Hexo site:** read the [Hexo guide](/docs/guides/hexo/) before
  mounting the repository.
- **I operate Tencent COS/CDN:** understand the current
  [Tencent provider status and safety gates](/docs/providers/tencent/).
- **I want to build an adapter:** begin with the
  [adapter model](/docs/adapters/overview/) and generated
  [v1 API reference](/docs/reference/adapter-api/).

:::caution[Current v0.1 status]
The filesystem vertical, provider-independent release behavior, and home-server
editor deployment are verified. Real Tencent staging and controlled production
publishing, provider-backed timing, and the signed v0.1.0 release remain gated.
The docs label planned or unverified behavior instead of presenting it as
shipped.
:::

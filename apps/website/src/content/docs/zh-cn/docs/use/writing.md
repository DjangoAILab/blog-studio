## 打开已有文档

配置的生成器适配器会发现内容集合并返回稳定文档引用。列举工作区是只读操作：未编辑文件保持逐字节一致。

打开文档时，如存在已确认草稿，Studio 显示最新草稿，否则显示文件源码。标题栏保存状态会区分本地变更、正在保存、已确认快照、错误和乐观版本冲突。

## 创建原生草稿

选择“新建文章”，输入标题，并可选提供小写 kebab-case slug。生成器适配器会在网站原生草稿集合中创建真实草稿；Hexo 对应 `source/_drafts`。遇到重复或不安全路径时会拒绝，而不是覆盖已有文件。

新文件与 SQLite 已确认快照职责不同：文件保持网站可迁移，快照让 Studio 自动保存且无需每次按键都重写 Git 跟踪内容。“放弃更改”只删除已确认快照并恢复原生文件，绝不删除 Markdown 文件。

## 选择合适的编辑模式

- **可视化模式**适合普通 Markdown 结构。
- **源码模式**是原始 HTML、Hexo 标签或可视化编辑器无法安全表达语法的无损出口。

检测到生成器专用结构时，Studio 可自动选择源码模式。切换模式本身不能产生草稿变更。

## 已确认保存意味着什么

自动保存响应包含单调递增的草稿版本。确认后，该版本会在浏览器刷新和服务重启后继续存在于挂载的 SQLite 数据库中。使用过期预期版本的请求会被拒绝为冲突，而不是悄然覆盖较新工作。

保存草稿**不会**提交 Git、重写源码文件、构建网站或发布；这些仍是显式发布操作。

发布原生草稿时，Studio 会在隔离工作区构建。只有上传、缓存失效和公网标记验证成功后，才把权威草稿提升到已发布集合并清除快照。构建或验证失败会让权威源码和已确认草稿保持不变。

## 冲突恢复

Studio 报告冲突时：

1. 复制需要保留的未保存文本；
2. 重新加载当前服务端草稿；
3. 在源码模式中协调两个版本；
4. 针对当前版本再次保存。

v0.1 是可信单用户产品，但乐观 revision 也能防止旧标签页覆盖内容，并为未来协作准备数据模型。

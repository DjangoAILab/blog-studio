粘贴或拖放的图片进入上传生命周期时，永久云凭据不会发送到浏览器。本地 object URL 先提供即时视觉反馈，服务端随后验证并存储资源。

## 键策略

新的受管键由以下内容组合：

- 配置的受管前缀；
- 不可变文档 ID；
- 内容哈希；
- 净化后的扩展名。

这样上传具备幂等性，新资源自然按文章分组。文件变化会产生新的不可变键，而不是覆盖已有缓存 URL 背后的字节。

## 图片策略

默认保留原图。禁用图片处理时，服务端检查声明的 MIME 类型和解码内容，然后原样保存字节、格式、语义扩展名和元数据，不会悄然转换为 WebP。

Site owner 可明确启用处理并选择原图或 WebP 输出、质量、最大宽度以及是否删除元数据。编码在有内存边界的 Worker 中运行且有硬超时；超时 Worker 会在调用 Provider 前终止。策略变更只影响新上传，不会重新压缩或重命名已有本地或远程资源。只有 Provider 返回持久公开 URL 后，编辑器才插入 Markdown。`ResourceRecord` 始终代表该上传结果，而非独立持久资源实体。

## 旧资源

已有资源路径不会自动迁移。将 `static` 等路径配置为受保护前缀，使 Studio 无法覆盖或删除它们。新文章范围资源与旧路径可以无限期共存。

采用基线后，即使后续生成器省略了受保护条目，Studio 仍会从已验证清单继承它们。如果受保护路径下生成的字节不同，基线字节仍为权威，发布日志会记录保留对象数量。基线中不存在的受保护生成路径会失败关闭；应把新文件移至配置的文章范围受管前缀。

## 删除未引用的受管资源

只有保存当前草稿后才能选择“检查未引用资源”。Studio 会列出文章范围资源，并将其精确公开 URL/键与已确认 front matter 和 Markdown 比较，只展示拟删除项、大小和数量，不执行删除。

删除需要第二次浏览器确认，以及服务端针对 source revision、draft version、asset ID 和内容哈希签发的 digest。任何输入变化都会返回冲突并要求重新预览。Provider 删除也会验证预期内容哈希。扫描仅限当前文档受管前缀，配置的旧/受保护前缀永远不会成为候选项。

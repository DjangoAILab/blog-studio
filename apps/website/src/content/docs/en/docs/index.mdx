## Work with AI without giving up your stack

<CardGrid>
  <Card title="Understand the whole Site" icon="seti:ai">
    Keep multiple durable, Site-scoped Agent Sessions. Attach an article,
    selection, editor buffer, preview error, or file only when it is relevant.
  </Card>
  <Card title="Make bounded changes" icon="pencil">
    Let the Agent read, search, create, edit, move, and remove files through
    typed tools constrained to the selected Site.
  </Card>
  <Card title="Review every AI action" icon="open-book">
    Require approval for modifications, inspect local Git changes, and preview
    with the real generator and theme before preparing a ChangeSet.
  </Card>
  <Card title="Publish under human control" icon="rocket">
    Commit and release through a separate reviewed workflow. The Site Agent has
    no remote or publishing tool and cannot bypass that decision.
  </Card>
  <Card title="Recover" icon="setting">
    Keep exact manifests and structured events so retries, cancellation, restart
    recovery, and rollback are explicit operations.
  </Card>
</CardGrid>

## Choose a path

- **I want to install it:** follow [Self-hosting](./guides/self-hosting/),
  then [configure a workspace](./configuration/workspaces/).
- **I have a Hexo site:** read the [Hexo guide](./guides/hexo/) before
  mounting the repository.
- **I want the AI workflow:** start with the [Site Agent guide](./use/agent/)
  and review its approval, file, Git, attachment, and recovery boundaries.
- **I operate Tencent COS/CDN:** understand the current
  [Tencent provider status and safety gates](./providers/tencent/).
- **I want to build an adapter:** begin with the
  [adapter model](./adapters/overview/) and generated
  [v1 API reference](./reference/adapter-api/).

:::note[Project finish line]
Blog Studio's product scope ends at AI-assisted production with human-reviewed
publishing. Autonomous publishing, a hosted Agent service, multi-user
collaboration, and deferred provider ecosystem work are outside this finish
line. The docs label unverified provider behavior instead of presenting it as
shipped.
:::

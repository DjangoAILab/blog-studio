# Blog Studio v0.2.0 Release Candidate

Blog Studio v0.2 turns the original writing surface into a Site-first,
recoverable publishing workbench. Markdown, Site files, and Git remain the
source of truth; SQLite stores owner credentials, revocable sessions, Site
identity, working copies, and immutable ChangeSet evidence without replacing
canonical content.

## Highlights

- Trusted CLI initialization and reset for the owner password, in-product
  password change, memory-hard versioned verifiers, and global session
  revocation. The normal browser journey no longer exposes the v0.1 opaque
  deployment token.
- Trusted Site discovery, preview-before-registration, durable display
  identity, settings with optimistic conflict handling, and capability
  diagnostics. Technical workspace details remain available only as advanced
  diagnostics.
- One content library for published articles, native drafts, and modified
  working copies, with body-free search, state/collection/tag/date filters,
  pagination, partial-source recovery, and source-conflict choices.
- Immediate sanitized Markdown preview for every supported document. Enhanced
  generator preview is reported ready only after the actual marked target
  responds successfully; every typed failure falls back to Markdown.
- Policy-controlled images and generic attachments with content sniffing,
  portable Markdown insertion, immutable article-scoped storage, contextual
  retry/rejection state, and exact orphan cleanup. Protected legacy resources
  are never silently moved or deleted.
- A calm `Prepare changes` action that freezes exact working-copy, resource,
  configuration, and Git revisions without writing files or contacting a
  Provider. Apply, selected-path local commit, and immutable remote release are
  separate, progressively confirmed, recoverable operations.
- The owner-selected Focused Workbench design: Site/content/system top
  navigation, opaque editorial surfaces, functional glass controls, responsive
  master/detail writing, accessible focus, and explicit reduced-motion,
  reduced-transparency, and increased-contrast fallbacks.

## Compatibility and operations

v0.2 migrates a copied v0.1 SQLite database transactionally and preserves
legacy drafts, releases, events, configuration, and Site files. Runtime images
include Git because selected-path local commit is a production capability, not
an optional development convenience. The hardened container remains non-root,
read-only-root compatible, and supports checksum-validated online backup,
restore, cold restart, credential reset, and Studio-only image rollback.

New installations and upgrades must follow the
[first-run guide](../guides/sites-and-first-run.md),
[upgrade guide](../guides/upgrading.md), and
[backup/restore guide](../guides/backup-restore.md). The exact candidate input
digest is reproducible with:

```sh
corepack pnpm candidate:manifest
```

The current release-candidate evidence and any remaining real-environment gate
are indexed in [v0.2 release-candidate verification](../verification/v0.2-release-candidate.md).

## Deliberate scope

v0.2 does not ship statistics, word-frequency analysis, AI writing controls,
Pi Agent/MCP integration, or the future GitHub Pages landing redesign. Those
are retained in the product evolution plan rather than represented by inactive
controls or unverified claims.

No production blog content release is part of release-candidate verification.
A production release still requires an explicit confirmation for that specific
attempt.

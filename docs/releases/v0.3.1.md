# Blog Studio v0.3.1

Blog Studio now opens without a password by default, matching its primary use
as a local or trusted-LAN content workspace. The browser still establishes a
signed session, and every mutation remains protected by exact-origin and CSRF
validation.

## Access modes

- `BLOG_STUDIO_AUTH_MODE=none` is the default. Anyone who can reach the allowed
  browser origin can edit.
- `BLOG_STUDIO_AUTH_MODE=password` retains Owner-password login, password
  rotation, session revocation, and trusted CLI recovery.

Use password mode for untrusted LANs, shared hosts, tunnels, or broader network
exposure. Existing password verifiers remain in SQLite when switching modes, so
an operator can switch back without recreating credentials.

## Upgrade

Recreate the container with the release image. Existing deployments that must
keep a login screen should add this before upgrading:

```dotenv
BLOG_STUDIO_AUTH_MODE=password
```

The home-server Blog Editor intentionally uses `none`.

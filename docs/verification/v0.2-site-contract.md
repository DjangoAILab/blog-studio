# v0.2 Site Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- A v0.1 workspace configuration remains valid without a `site` block. An
  optional `site.displayName` and HTTP(S) `site.canonicalUrl` may provide the
  proposed public identity without replacing the technical workspace binding.
- An authenticated owner can list registered Sites, discover trusted
  unregistered configurations, review identity/content counts/resource policy,
  repository state/capabilities and diagnostics, confirm registration, read one
  Site, and update supported Site metadata.
- Public Site responses omit `workspaceId`, workspace roots, and configuration
  paths. Those technical values appear only in the discovery candidate's
  `advanced` diagnostics before confirmation.
- Registration persists a stable random Site ID, display identity, canonical
  URL, technical binding, capability snapshot, and timestamps in SQLite.
- Display names are case-insensitively unique. Settings updates require the
  exact `updatedAt` revision and reject stale writes. URL validation accepts
  HTTP(S) only. Updating Site metadata does not rewrite the source YAML.
- Workspace loading resolves real paths and rejects both direct and
  symlink-mediated escapes from the administrator allowlisted root before a
  candidate can be discovered.

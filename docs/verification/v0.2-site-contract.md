# v0.2 Site Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- A v0.1 workspace configuration remains valid without a `site` block. An
  optional `site.displayName` and HTTP(S) `site.canonicalUrl` may provide the
  proposed public identity without replacing the technical workspace binding.
- An authenticated owner can list registered Sites, discover trusted
  unregistered configurations, review identity/content counts/capabilities and
  diagnostics, confirm registration, read one Site, and update supported Site
  metadata.
- Public Site responses omit `workspaceId`, workspace roots, and configuration
  paths. Those technical values appear only in the discovery candidate's
  `advanced` diagnostics before confirmation.
- Registration persists a stable random Site ID, display identity, canonical
  URL, technical binding, capability snapshot, and timestamps in SQLite.
- Display names are case-insensitively unique. Settings updates require the
  exact `updatedAt` revision and reject stale writes. URL validation accepts
  HTTP(S) only. Updating Site metadata does not rewrite the source YAML.
- Workspace loading resolves real paths and rejects both direct and
  symlink-mediated escapes from the administrator allowlisted root before a
  candidate can be discovered.

  server/test/sites.test.ts server/test/app.test.ts \

discovery, previewed content counts and advanced diagnostics, confirmation,
public-contract redaction, settings update, stale conflict, duplicate display
identity, URL policy, source-config non-mutation, direct root escape, and
symlink escape.

Results: Studio 9 files/49 tests, Core 2 files/14 tests, Config 1 file/11 tests;

website link check, and formatting passed for all 16 packages.

## Deliberately not claimed yet

- The production UI is not Site-first yet and no onboarding browser journey is
  claimed here.
- Discovery does not yet expose a full Git repository status or a normalized
  resource-policy summary.
- The real `wj2015-blog` installation has not yet been registered through this
  contract; that requires a disposable copy or explicit non-production runtime
  verification before checking the release item.
- Site metadata has revision evidence but not a separate append-only audit
  event stream.

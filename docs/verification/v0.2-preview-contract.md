# v0.2 Preview Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- Every Site document can request an immediate, generator-independent Markdown
  preview backed by the current SQLite working copy or canonical source.
- Markdown conversion disables raw HTML execution. Local resource URLs are
  rewritten through a Site-scoped, realpath-checked endpoint; dangerous link
  protocols are blocked. Preview HTML and resources use sandboxed CSP,
  `nosniff`, no-referrer, and no-store/private-cache headers.
- Enhanced preview writes a unique hidden marker only inside an isolated
  workspace sandbox. It is not ready merely because the generator process
  exited: the resolved document target must exist, be a file, and contain that
  exact marker.
- Missing output, output without the marker, and build failure return a ready
  Markdown preview with typed `missing-output`, `route-error`, or `build-error`
  reasons. Timeout and unsupported-engine reasons are typed separately.
- Existing enhanced-preview reuse, explicit stop, expiry reaping, asset URL
  rewriting, native-draft promotion, and sandbox cleanup regressions remain
  green.

## Reproducible evidence

Focused sanitization, readiness, and fallback suite:

```sh
corepack pnpm --filter @blog-studio/studio exec vitest run \
  server/test/preview-fallback.test.ts server/test/app.test.ts \
  -t "Markdown|enhanced preview|preview reports"
```

Result: 2 files passed; 6 tests passed. The journey renders a Markdown working
copy, proves raw script markup cannot execute, loads a legacy image through the
scoped resource route, verifies CSP, starts an enhanced preview, fetches its
actual target, and observes the session marker. Three production-shaped failure
fixtures prove missing target, missing marker, and build failure fall back to a
working Markdown URL. A unit boundary proves unsupported generators are
rejected before sandbox creation.

Full Studio and repository gates:

```sh
corepack pnpm --filter @blog-studio/studio test
corepack pnpm check
corepack pnpm format:check
```

Results: Studio 10 files/57 tests passed. Policy smoke, lint, typecheck, all
package tests, production builds, website link check, and formatting passed for
all 16 packages.

## Deliberately not claimed yet

- The production UI still invokes the legacy enhanced-only endpoint. The
  selected Site-first UI must consume this fallback contract before the
  end-to-end “preview always works” checklist item is checked.
- Cancellation and process restart have typed reason vocabulary but do not yet
  restore or redirect an already-issued in-memory preview URL.
- Raw HTML is intentionally displayed as text in Markdown mode. Theme/plugin
  fidelity belongs exclusively to the isolated enhanced mode.

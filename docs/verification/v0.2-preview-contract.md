# v0.2 Preview Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- Every Site document can request an immediate, generator-independent Markdown
  preview backed by the current SQLite working copy or canonical source.
- Markdown conversion disables raw HTML execution. Local resource URLs are
  rewritten through a Site-scoped, realpath-checked endpoint; dangerous link
  protocols are blocked. Preview HTML and resources use sandboxed CSP,
  `nosniff`, no-referrer, and no-store/private-cache headers.
- Enhanced preview writes a unique hidden marker only inside an isolated
  workspace sandbox. It is not ready merely because the generator process
  exited: the resolved document target must exist, be a file, and contain that
  exact marker.
- Missing output, output without the marker, and build failure return a ready
  Markdown preview with typed `missing-output`, `route-error`, or `build-error`
  reasons. Timeout and unsupported-engine reasons are typed separately.
- The currently shipped Workspace UI uses the same fallback behavior. When
  enhanced preview fails, the preview panel remains usable, identifies the
  reason in owner-facing language, and states that the rendered result is the
  Markdown fallback instead of presenting a generic server error.
- Site preview cancellation now propagates through the generator adapter to the
  spawned process. The stop response waits for process exit and sandbox removal;
  the pending preview request resolves to a ready Markdown result with the typed
  `canceled` reason.
- Preview sandboxes live below a dedicated operational-state directory. Startup
  rejects a symlink in place of that root and removes interrupted prior-process
  entries before the server becomes ready. Existing success/failure cleanup,
  explicit stop, expiry reaping, asset URL rewriting, native-draft promotion,
  and canonical-workspace isolation regressions remain green.

  server/test/preview-fallback.test.ts server/test/app.test.ts \
  -t "Markdown|enhanced preview|preview reports|in-flight Site preview|preview sandboxes"

proves raw script markup cannot execute, loads a legacy image through the scoped

fixtures prove missing target, missing marker, and build failure fall back to a
working Markdown URL. Additional service and HTTP tests prove unsupported
generators are rejected before sandbox creation, in-flight cancellation kills
the command and waits for removal, startup reclaims an interrupted directory,
and the Site API returns the usable `canceled` Markdown fallback.

## Deliberately not claimed yet

- The selected Site-first UI still needs to expose an explicit Markdown versus
  enhanced-mode control; the current compatibility surface tries enhanced mode
  first and falls back automatically.
- An already-issued enhanced-preview URL is intentionally ephemeral and is not
  restored across process restart; the owner can immediately request a new
  Markdown or enhanced preview after health returns.
- Raw HTML is intentionally displayed as text in Markdown mode. Theme/plugin
  fidelity belongs exclusively to the isolated enhanced mode.

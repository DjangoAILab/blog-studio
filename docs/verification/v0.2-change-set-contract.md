# v0.2 ChangeSet and Local Commit Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Contract now covered

- `Prepare changes` reads the Site's working copies and local Git state into an
  immutable SQLite ChangeSet. It does not write canonical content, run the
  generator, contact a publish/cache Provider, push Git, or verify a public URL.
- Source revisions, full working-copy bodies/front matter and versions, Git
  head/branch, managed diffs, untracked paths, ignored paths, staging state, and
  current file hashes participate in the frozen review or fingerprint.
- Identical inputs return the existing prepared ChangeSet. A changed working
  copy or repository state creates a new ChangeSet and supersedes the old review.
- Apply rechecks the Git head/state plus every source and draft revision. A stale
  input invalidates the review with `CHANGE_SET_CONFLICT` and is not overwritten.
- Apply is journaled before canonical writes. Synchronous failure rolls back
  already-written documents; startup recovery rolls back a recognizable target
  after an interrupted apply and refuses ambiguous external content.
- Local commit is a separate operation after apply. The API requires an editable
  message and explicit paths, rejects paths outside the review, requires every
  applied document, and records the resulting commit ID.
- The local Git adapter commits only selected paths, preserves unrelated staged
  work, restores the exact pre-operation index if commit creation fails, and
  never pushes.
- The Site-scoped remote-release endpoint accepts only a committed ChangeSet and
  an explicit confirmation phrase, records both immutable identifiers, and
  builds from a detached Git worktree at that commit rather than the live tree.

## Reproducible evidence

```sh
corepack pnpm --filter @blog-studio/persistence test
```

Result: 7 files and 26 tests passed, including migration v3, immutable
preparation, supersession, apply journals, and atomic apply-state completion.

```sh
corepack pnpm --filter @blog-studio/adapter-local-git test
```

Result: 1 file and 3 tests passed, covering read-only status/diff inspection,
selected-path commit with unrelated staged work, and exact index restoration on
commit failure.


Result: the Site API journey passed prepare, repeated prepare, supersession,
review history, apply, explicit-path local commit, unrelated-file preservation,
stale-apply rejection, and a separately confirmed release. The release fixture
proved that an uncommitted live-tree edit was absent from the published output.

Result: the simulated crash/restart test restored the original source from the

## Deliberately not claimed yet

- Configuration files outside the Site Git root do not yet have a frozen
  revision, so the full cross-store revision checklist item remains open.
- The review API exposes file diffs and states, but the human review UI and its
  document/resource summaries are not implemented yet.
- The legacy workspace-scoped release endpoint remains for v0.1 compatibility;
  it is not exposed by the new Site journey and still prevents checking the
  stronger statement that every possible API release requires a ChangeSet.

# v0.2 ChangeSet and Local Commit Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Contract now covered

- `Prepare changes` reads the Site's working copies and local Git state into an
  immutable SQLite ChangeSet. It does not write canonical content, run the
  generator, contact a publish/cache Provider, push Git, or verify a public URL.
- Source revisions, full working-copy bodies/front matter and versions,
  referenced resource records and content hashes, the Site configuration hash,
  Git head/branch, managed diffs, untracked paths, ignored paths, staging state,
  and current file hashes participate in the frozen review or fingerprint.
- Identical inputs return the existing prepared ChangeSet. A changed working
  copy or repository state creates a new ChangeSet and supersedes the old review.
- Apply rechecks the Git head/state, Site configuration, every source and draft
  revision, and every referenced resource. A stale input invalidates the review
  with `CHANGE_SET_CONFLICT` and is not overwritten.
- Apply is journaled before canonical writes. Synchronous failure rolls back
  already-written documents; startup recovery rolls back a recognizable target
  after an interrupted apply and refuses ambiguous external content.
- Local commit is a separate operation after apply. The API requires an editable
  message and explicit paths, rejects paths outside the review, requires every
  applied document, and records the resulting commit ID.
- The local Git adapter commits only selected paths, preserves unrelated staged
  work, restores the exact pre-operation index if commit creation fails, and
  never pushes.
- The Site-scoped remote-release endpoint accepts only a committed ChangeSet and
  an explicit confirmation phrase, records both immutable identifiers, and
  builds from a detached Git worktree at that commit rather than the live tree.

## Deliberately not claimed yet

- The review API exposes file diffs and states, but the human review UI and its
  document/resource summaries are not implemented yet.
- The legacy workspace-scoped release endpoint now returns HTTP 410 by default.
  A server-only compatibility option can temporarily re-enable it for controlled
  v0.1 migration tests, so the stronger statement that no deployed configuration
  can ever bypass ChangeSet review remains deliberately unchecked.

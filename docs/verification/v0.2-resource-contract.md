# v0.2 Resource Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Contract now covered

- The resource domain distinguishes optimized images from policy-controlled
  attachments while preserving one portable insertion contract.
- Site capabilities expose accepted media types and the maximum input size.
- PNG, JPEG, and WebP inputs continue through the existing image optimizer and
  produce immutable WebP resources.
- Allowed PDF, ZIP, and UTF-8 text inputs retain their original bytes and use
  content-hash storage names.
- The configured policy bounds media types and bytes; the server validates the
  supplied filename, detected content, extension, and declared media type.
- Executable signatures, MIME spoofing, mismatched extensions, invalid UTF-8,
  oversized inputs, and traversal-shaped filenames have focused tests.
- The Site-scoped upload endpoint returns the complete resource record only
  after durable storage succeeds.
- The contextual editor status distinguishes safety checking, retryable provider
  failure, policy rejection before storage, ready local/remote storage, and
  unreferenced resources. There is no standalone resource-management surface.
- Policy and executable failures preserve their typed error code through HTTP,
  so the browser says `已拒绝，未存储` instead of offering a futile retry.
- Unreferenced-resource review is Site-scoped. Its delete request must present
  the exact source/draft/resource fingerprint just reviewed; the server rebuilds
  the plan and rejects stale confirmation before deleting any object.

## Deliberate boundary

“Any resource” means any type admitted by the explicit Site policy. Executable
content remains prohibited even if its declared MIME type is misleading. v0.2
rejects suspicious input before durable storage, so it does not create a
quarantine lifecycle it cannot operationally guarantee.

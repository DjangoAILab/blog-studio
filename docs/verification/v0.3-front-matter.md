# v0.3 Front-matter Preservation Evidence

## Scope

The authoring implementation preserves canonical Hexo front matter while a
working copy is edited, exposes common and Site-defined fields, and provides a
guarded YAML repair route for malformed canonical metadata.

## Automated checks

- `CI=true corepack pnpm --filter @blog-studio/adapter-hexo test` verifies a
  title edit keeps an untouched comment, key order, quoted scalar, list/scalar
  shape, and nested YAML comment. It also verifies malformed source remains
  readable and cannot be overwritten by a structured save.
- `CI=true corepack pnpm --filter @blog-studio/persistence test` verifies the
  source YAML retained with a draft survives persistence and migration from a
  v0.2 database.
- `CI=true corepack pnpm --filter @blog-studio/studio test -- app.test.ts`
  covers Site field capability publication, default application to native
  drafts, invalid-source diagnostics, and revision-checked canonical YAML
  repair. It passed on 2026-08-07.
- `CI=true corepack pnpm --filter @blog-studio/studio exec playwright test
e2e/authoring.spec.ts` creates a native draft, sets tags and category, waits
  for autosave, reloads the browser, and asserts taxonomy plus configured
  boolean/select fields are restored. It also enters source-repair mode after
  a malformed canonical header is detected.

## Current boundary

Custom-field definitions are validated as typed, non-ambiguous configuration:
standard keys cannot be redefined, defaults must match field types, enums are
restricted to string/list fields, and only scalar fields are sortable. The
advanced editor accepts supported YAML mappings; normal changes retain untouched
YAML CST nodes, while a repair deliberately replaces only a malformed header
after revision verification and refuses to run with a working copy present.

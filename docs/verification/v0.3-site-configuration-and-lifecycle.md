# v0.3 Site configuration and lifecycle verification

**Captured:** 2026-08-07.

## Verified contract

- Owner-editable YAML is a strict versioned model: only `content.fields` and
  `development` are accepted. Credentials, workspace paths, adapters, publish
  targets, and unknown top-level policy are rejected.
- Activation validates YAML before an atomic `0600` replacement, records an
  immutable revision, dynamically refreshes the workspace model, and supports
  history and revert. A stale revision is rejected.
- Registering a Site creates the initial managed configuration so ChangeSets
  freeze the managed configuration file rather than host policy YAML.
- Changing that configuration invalidates a prepared ChangeSet before any
  canonical content or Git mutation.
- Active, paused, and unregistered states are revision-checked. Paused and
  unregistered Sites reject working content and release paths; pausing stops
  the development process and recovery restores the Site without deleting its
  checkout or target.
- Native filesystem publishing rejects lexical overlap with a configured
  workspace, Studio state, or another configured workspace before a Provider
  runs.

## Automated and production-like evidence

The final source state must pass all of the following without replacing a
narrow focused result with a broad claim:

```sh
CI=true corepack pnpm check
CI=true corepack pnpm format:check
CI=true corepack pnpm --filter @blog-studio/studio e2e
CI=true corepack pnpm candidate:manifest
```

The exact Linux amd64 image then runs the isolated commands recorded in
[container and operations verification](./v0.2-operations.md): quick start,
hardened container smoke, and operations smoke. Together they cover trusted
password initialization, Site registration, Git availability, unified content,
real preview, non-root/read-only-root enforcement, cold restart, interrupted
preview cleanup, fail-closed invalid configuration, online SQLite backup,
checksum verification, destructive fixture mutation, restore, credential reset,
and old-session invalidation.

## Real home-server boundary

[The home-server candidate record](./v0.2-home-server-candidate.md) is the
authoritative inventory for the current image, pre-upgrade backup, rollback
image, Compose hashes, canonical workspace revision, and public payload hashes.
The only allowed production deployment mutation is a Studio-only image switch;
no canonical Markdown, Git revision, generated public tree, cache, object
storage, or release Provider is changed by that operation.

The exact image is running after a successful Studio-only switch, application
rollback rehearsal, forward recovery, and final cold container recreation. The
owner initialized generation-1 credentials through the trusted CLI; the real
browser then retained login, registered `wj2015-blog`, listed 93 published and
5 native-draft documents, edited/reloaded/discarded a published working copy,
loaded 21 Markdown-preview images through sandbox capability URLs, observed a
truthful enhanced-preview route fallback, and prepared a frozen ChangeSet
without applying it. Authenticated production measurements were recorded, the
final modified count is zero, and the canonical workspace/public payload stayed
revision-for-revision and byte-for-byte stable.

## Safety boundary

Browser and release failure journeys use auto-deleted Git fixtures,
filesystem-only publishing, and `example.invalid`. Linux amd64 container
acceptance uses isolated temporary directories and ports. No production blog
content release is initiated without an explicit contemporaneous owner
confirmation, and none is required to accept v0.2's authoring/control-plane
upgrade.

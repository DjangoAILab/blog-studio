# v0.2 Content Workbench Verification

**Verified:** 2026-08-05. **Scope:** the unified library, Site-scoped editor,
generic resource insertion, and Markdown/enhanced preview slices of Task 12.

## Product contract implemented

- The content library consumes `GET /api/sites/:siteId/content` and presents
  published documents, native drafts, and modified working copies in one list
  with stable state labels and server-provided totals.
- Title/path/tag search plus collection, state, canonical-update date, and
  front-matter tag filters operate on content summaries; article bodies are
  fetched only after selection. Server-provided facets populate the compact
  advanced-filter form without downloading bodies.
- New drafts use `POST /api/sites/:siteId/content`. Reading, autosave, discard,
  resource upload, and preview also use Site-scoped routes. The production
  `StudioApp` no longer calls legacy workspace document routes.
- The editor accepts every media type advertised by the Site capability. Images
  preserve the optimized path; a verified text attachment journey inserts the
  portable Markdown link returned by the resource API. Uploading, success,
  retryable failure, policy rejection, local/remote durability, orphan review,
  and stale-plan-safe cleanup remain contextual to the article.
- `预览全文` opens the guaranteed Markdown renderer first. The owner may
  explicitly request the Site theme; the preview pane reports typed fallback
  reasons and retains a visible return-to-edit action.
- Loading and no-match states remain inside the library rather than replacing
  navigation. An incompatible collection produces a partial warning while
  healthy collections remain usable; a source-unavailable working copy appears
  as a metadata-only recovery row with an explicit, version-checked delete
  action that never touches canonical files.

The desktop composition is a rounded two-surface master/detail workbench. The
content library remains visible while the right surface changes between editor
and preview, avoiding the rigid three-column composition. At mobile widths,
the same three logical panels become one-at-a-time views behind the labelled
`文章 / 写作 / 预览` control.

## Automated evidence

The focused Studio suite passed with **71 active tests** and one intentionally
skipped fixture. The focused authoring browser journey passed in **16.5 seconds**
and proves:

1. A published article is visible in the unified library.
2. State filtering and title/path-capable search return the published article;
   collection, front-matter tag, and inclusive date filters compose correctly.
3. A native draft is created through the Site route, autosaved, reloaded, and
   discarded without changing its canonical Markdown source before apply.
4. A `text/plain` attachment is policy-checked, stored, and inserted as a
   portable Markdown link.
5. Markdown preview renders in the sandboxed iframe; enhanced preview falls
   back with an explicit diagnostic when the fixture cannot prove readiness.
6. The owner can return from preview to editing.
7. At 390×844, the mobile panel control is visible, exactly one workbench panel
   is rendered, and the document has no horizontal overflow.
8. A published article is edited, autosaved, reloaded and remains a working copy
   until an explicit ChangeSet apply.
9. If that article changes on disk, normal editing is frozen while both versions
   remain visible; rebasing retains the owner's body on the latest source
   revision before preparation continues.
10. Loading, empty-filter, partial collection failure, incompatible source,
    and retained working-copy recovery states stay navigable on desktop and
    mobile and pass the same serious/critical axe scan.
11. A temporary resource-provider failure is retryable; approved text files
    show durable storage, an executable is rejected before storage, and exactly
    two unreferenced resources are reviewed and cleaned with confirmation.

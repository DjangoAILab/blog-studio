# v0.2 Unified Content Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- `GET /api/sites/:siteId/content` merges published documents, generator-native
  drafts, and SQLite working copies into one stable summary contract with
  `published`, `draft`, and `modified` states and totals.
- The query supports title/path/tag text search, exact collection/state/tag
  filters, inclusive date boundaries, deterministic sorting, and bounded
  pagination.
- The response includes collection, tag, and canonical-update date facets
  computed from metadata summaries before filtering. The browser exposes these
  as a compact advanced-filter form and sends full UTC boundary timestamps.
- Summary queries do not return document bodies. SQLite uses a metadata-only
  draft projection, while generator adapters return hashes, titles, tags,
  paths, dates, and source state.
- A published document can be opened and saved as a versioned SQLite working
  copy without changing its canonical Markdown file. The same contract reloads
  and discards that copy with an exact optimistic version.
- A native draft remains a native draft in the unified query and preserves its
  existing create/edit flow.
- Native-draft promotion remains revision-checked and moves exactly the
  selected draft only after verified release; enhanced preview performs any
  needed promotion inside its disposable sandbox.
- Every summary carries the current canonical revision. If the file changes
  outside Studio, the working copy is marked `stale`; both the new Site API and
  compatibility Workspace API reject another save with a typed
  `DOCUMENT_CONFLICT` instead of overwriting either version.
- One incompatible collection no longer collapses the library: the response
  includes a typed collection issue, returns summaries from healthy
  collections, and exposes any affected SQLite working copy as a metadata-only
  recovery item. Its body never enters the summary response.
- A recovery item can delete only its SQLite working copy, after an optimistic
  version check and a fresh proof that no canonical source with that document
  ID is currently readable. The action never deletes or rewrites a Site file.

edits it, proves the canonical file is unchanged, creates a native draft,
checks totals/pagination/search/path/collection/state/tag/date filters, detects
an external source change, rejects a stale save, rejects a stale discard, and
discards the exact working-copy version.

update date, and state filters after a title/path-capable search. A regression

## Deliberate boundary

Working copies are not written to canonical files by the library itself. Exact
application remains reserved for the reviewed ChangeSet flow.

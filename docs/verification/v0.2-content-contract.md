# v0.2 Unified Content Contract Verification

Verified on 2026-08-04 on branch `codex/v0.2-site-foundation`.

## Verified behavior

- `GET /api/sites/:siteId/content` merges published documents, generator-native
  drafts, and SQLite working copies into one stable summary contract with
  `published`, `draft`, and `modified` states and totals.
- The query supports title/path/tag text search, exact collection/state/tag
  filters, inclusive date boundaries, deterministic sorting, and bounded
  pagination.
- Summary queries do not return document bodies. SQLite uses a metadata-only
  draft projection, while generator adapters return hashes, titles, tags,
  paths, dates, and source state.
- A published document can be opened and saved as a versioned SQLite working
  copy without changing its canonical Markdown file. The same contract reloads
  and discards that copy with an exact optimistic version.
- A native draft remains a native draft in the unified query and preserves its
  existing create/edit flow.
- Every summary carries the current canonical revision. If the file changes
  outside Studio, the working copy is marked `stale`; both the new Site API and
  compatibility Workspace API reject another save with a typed
  `DOCUMENT_CONFLICT` instead of overwriting either version.

## Deliberately not claimed yet

- The existing UI still performs its own draft/post grouping. The Site-first
  library surface and browser accessibility evidence belong to the selected UI
  direction and are not checked in the release checklist yet.
- Orphaned working-copy metadata for a deleted or incompatible source is not
  yet returned as a navigable partial-error item.
- Working copies are not written to canonical files by this milestone. Exact
  application is reserved for the reviewed ChangeSet flow.

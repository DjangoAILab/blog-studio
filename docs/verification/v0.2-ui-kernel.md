# v0.2 Focused Workbench UI Kernel Verification

**Verified:** 2026-08-05. **Scope:** Task 10, the first Site-first slice of Task
11, and the content-workbench slice of Task 12.

## Implemented target

The repository owner approved the refined **Focused Workbench** direction. The
production client now uses:

- `@base-ui/react` for the keyboard- and focus-managed Site menu and ChangeSet
  dialog;
- `motion` for the shared navigation indicator, page presence, layout response,
  and reduced-motion policy;
- semantic plain-CSS tokens for content, functional glass, elevation,
  typography, spacing, radii, focus, state color, and fallbacks;
- one Site-first top navigation with `站点 / 内容 / 系统`; contextual resources
  remain in the editor and are not a primary destination;
- a first-run discovery and confirmation screen, real Site overview, system
  security screen, and a safe `准备更改` review sheet backed by the durable
  ChangeSet API.

The content canvas remains opaque. Blur is limited to the functional navigation,
Site menu, bottom destination control, ready capsule, backdrop, and transient
review sheet. `prefers-reduced-motion`, `prefers-reduced-transparency`,
`prefers-contrast`, and no-`backdrop-filter` fallbacks are encoded in
[`studio.css`](../../apps/studio/src/styles/studio.css).

## Automated evidence

The following commands passed on the owner workstation:

```text
corepack pnpm --filter @blog-studio/studio typecheck
corepack pnpm --filter @blog-studio/studio lint
corepack pnpm --filter @blog-studio/studio build
corepack pnpm --filter @blog-studio/studio test
corepack pnpm --filter @blog-studio/studio e2e
```

The full repository check passed after the ChangeSet client assertion was
added. The Studio suite retained its one intentionally skipped fixture, and all
active tests passed. The added assertion proves that `准备更改` uses
`/change-sets/prepare` and never a release endpoint.
The current two-test browser suite passed in 14.4 seconds after the fixture was
made a real local Git Site. It exercises:

1. Owner-password login;
2. trusted Site discovery, preview, confirmation, and registration;
3. native draft creation, autosave, reload, and source recovery;
4. Markdown preview fallback;
5. ChangeSet preparation and review with no publish action;
6. working-copy discard;
7. in-product password change, other-session revocation, logout, and login with
   the replacement password.

`@axe-core/playwright` now scans stable first-run, invalid-configuration,
onboarding, library/editor, preview, settings, mobile, and adapted-media states
against WCAG 2 A/AA and WCAG 2.1 A/AA. The first run exposed low-contrast legacy
tokens; the workbench exposed an unnamed ProseMirror surface, transient
text-opacity animation, low-contrast secondary text, undefined state/separator
tokens, and a mobile icon-only accessible-name regression. All were corrected,
and the suite now reports zero serious or critical violations at every scan.

Chromium DevTools media emulation proves all three product queries match:
`prefers-reduced-motion: reduce`, `prefers-reduced-transparency: reduce`, and
`prefers-contrast: more`. In that state the navigation has no backdrop filter,
its stronger border is active, affected CSS transitions are at most `0.00001s`,
and the final axe scan remains clean. Native roles/names and visible focus are
asserted throughout the same keyboard-capable browser journey.

The interaction performance fixture also passed with 93 documents: content
listing p95 was 8.3 ms, acknowledged autosave p95 was 2.3 ms, navigation-frame
p95 was 9.2 ms, and no frame exceeded 50 ms. Reproduction details and the
explicit budgets are recorded in
[the performance verification](./v0.2-performance.md).

## Visual and responsive evidence

The running production build was inspected in the in-app browser at 1280×720
and 390×844 after each screen reached its stable state.

- Desktop first run uses one optically aligned column, a two-surface discovery
  confirmation layout, and no standalone resource destination.
- Desktop Site overview keeps the title, status rail, section heading, and
  grouped content list on the same column anchors.
- Mobile Site overview uses a compact Site/action bar and a separate bottom
  destination control. A containing-block issue caused by mobile nav blur was
  found during inspection and fixed before this record.
- Desktop and mobile content transitions retain a visible preview action and
  exactly one active editor panel.
- Read-only browser metrics reported no horizontal overflow at either viewport
  and no console errors.

The editor now uses the selected two-surface master/detail composition rather
than the legacy rigid three-panel frame. Its runtime contract and evidence are
recorded separately in
[the content workbench verification](./v0.2-content-workbench.md).

No local commit, remote release, or production-blog mutation was initiated by
this verification.

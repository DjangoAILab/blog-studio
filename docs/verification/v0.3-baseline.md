## Repository state

The implementation begins from the v0.2 Site-first workbench plus the
owner-approved v0.3 lifecycle design and checklist. The worktree was clean
before creating this evidence record. The reference content repository remains
outside this repository and was only read during design: it contains 93 Hexo
posts, each with `title`, `date`, `tags`, `categories`, and `cover`; categories
appear as both scalar and array forms.

## Baseline gates

The following commands passed locally with the declared runtime:

```sh
CI=true corepack pnpm check
CI=true corepack pnpm format:check
```

`check` passed the Tencent policy smoke, lint, type checks, all package test
suites, and production builds. Turbo reported 17 successful package build/test
tasks; the Studio production build retained its existing chunk-size warnings but
completed successfully. Prettier reported all files formatted.

## Known observed gaps

- The Markdown preview canvas has a CSS Grid auto-placement error when its
  fallback banner is absent, yielding an iframe-height preview instead of using
  the available panel height.
- Content ordering uses front-matter `updated` then filesystem mtime. The
  reference repository's checkout mtime does not represent article recency.
- The top navigation search button only navigates to Content and does not focus
  or submit a query, despite the API supporting search.
- Working copies persist parsed front-matter objects but not a lossless YAML
  representation; normal future edits would need a preservation layer before
  exposing metadata controls.
- Site configuration is startup-only and environment-path based. Existing
  generator, filesystem-publisher, and release capabilities lack an owner
  lifecycle/configuration control plane and persistent local-development
  supervisor.

# Website and documentation verification — 2026-08-02

## Scope

This evidence covers the Blog Studio product landing page, Starlight
documentation, generated configuration and adapter references, responsive
behavior, accessibility, links, search, and local static-site performance.

The public copy was checked against implemented behavior. It presents Hexo and
Tencent as the first vertical, labels the real Tencent and home-server work as
pending, and does not advertise collaboration, scheduling, or AI writing as
shipped v0.1 features.

## Reproducible checks

Run from the repository root:

```sh
CI=true corepack pnpm --filter @blog-studio/website lint
CI=true corepack pnpm --filter @blog-studio/website typecheck
CI=true corepack pnpm --filter @blog-studio/website test
CI=true corepack pnpm --filter @blog-studio/website e2e
CI=true corepack pnpm --filter @blog-studio/website audit:lighthouse
```

Observed results:

- ESLint passed.
- Astro check examined 12 files with zero errors, warnings, or hints.
- Vitest passed 3 of 3 tests.
- Astro generated 18 static pages; Pagefind indexed all 18 pages; the internal
  link checker passed.
- Playwright passed 8 of 8 browser checks in desktop Chrome and a Pixel 7
  viewport. The checks cover the landing-page claims, navigation, deep links,
  Pagefind search, narrow-layout overflow, and axe WCAG 2 A/AA and 2.1 A/AA
  serious/critical violations.
- No serious or critical axe violations were found on the landing page, docs
  home, or publishing guide in either browser profile.

The sitemap warning during a local build is expected. A canonical `site` value
will be set when the documentation deployment URL is selected; inventing a URL
before deployment would generate incorrect canonical and sitemap locations.

local preview, launches Chrome, audits the four cases below, enforces category
scores of at least 90 (95 for accessibility), CLS at most 0.1, and LCP at most
2.5 seconds, then stops both processes.

## Visual and runtime review

The final static build was inspected at 1440 by 1000 pixels and 390 by 844
pixels in Chrome. The editorial hierarchy, product mock, calls to action,
adapter diagram, docs cards, navigation, and footer remained legible and
balanced at both widths. Automated inspection reported:

- exact equality between document width and viewport width for the desktop and
  mobile landing pages and the desktop docs page;
- no browser console errors;
- no page errors; and
- no HTTP responses with a status of 400 or greater.

The contrast palette was adjusted after axe identified low-contrast accent and
mock-interface text. The final palette retains the paper, ink, terracotta, and
moss direction while passing the automated WCAG gate.

## Generated-reference integrity

`pnpm docs:generate` reads the committed workspace JSON Schema and adapter
TypeScript contracts before formatting the generated Markdown. The regular
build runs the generator first, so source/reference drift is caught as a dirty
worktree or formatting failure rather than silently shipping stale API docs.

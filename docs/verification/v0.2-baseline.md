## Persistence baseline

`packages/persistence/src/database.ts` currently applies one unversioned,
idempotent SQL string on every open. It creates:

- `drafts` keyed by technical `workspace_id` and `document_id`;
- durable `jobs` and lease state;
- `releases` plus the one-active-target partial unique index;
- ordered `release_events`.

There is no migration ledger, credential/session store, Site table, or
ChangeSet table. Therefore the first v0.2 storage change must treat this exact
shape as the legacy baseline, preserve its rows, apply numbered migrations in a
transaction, and reject a database created by an unknown future schema.

## Product gaps reproduced before implementation

The authenticated product inspection on 2026-08-04 established these gaps:

1. login asks for an opaque deployment token;
2. the primary navigation exposes drafts but not a coherent published-content
   management journey;
3. a local generator fixture returned preview session state as ready, while
   fetching the advertised iframe target returned HTTP 500 with `ENOENT`,
   leaving a blank preview;
4. the upload contract accepts only PNG/JPEG/WebP images;
5. the primary action starts a remote release rather than preparing a safe,
   reviewable local change;
6. technical workspace configuration is pre-provisioned by an operator; there
   is no first-run Site discovery/confirmation/settings journey.

The preview observation is not yet protected by an automated regression. Task
6 must first encode READY-plus-missing-target as a failing test, then require a
real target response and session marker.

## Existing real-environment invariants to preserve

The last accepted deployment evidence proves:

- Studio is isolated from the public blog fault domain;
- the container runs as UID/GID `1000:1000`, read-only root, dropped
  capabilities, and `no-new-privileges`;
- current secret files are mode `0600` and not printed;
- a real reference preview keeps the canonical workspace Git-clean;
- backup/restore and cold-restart draft recovery work;
- production publishing is protected and staging uses an isolated prefix;
- the public root and sampled legacy resources remain available when Studio is
  stopped.

All of these are v0.2 non-regression gates. No production content release is
authorized by this document or by the v0.2 Goal.

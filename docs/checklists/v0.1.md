# v0.1 Release Checklist

Every required item must have reproducible evidence. A checked box without a
command, test artifact, screenshot, log, or production observation is invalid.

## Repository and governance

- [x] Public GitHub repository exists under DjangoAILab.
- [x] Apache-2.0 license is detected by GitHub.
- [ ] `main` is protected by required CI checks.
- [x] README explains status, value, quick start, and architecture.
- [ ] CONTRIBUTING, SECURITY, support, and code-of-conduct documents exist.
- [ ] dependency update and release automation are configured.

## Architecture conformance

- [x] Core has no import from Hexo, COS, Tencent, GitHub, or Traefik packages.
- [x] Generator, asset, publisher, cache, and repository contracts are versioned.
- [x] Built-in adapters pass reusable conformance suites.
- [x] Configuration is schema-validated with actionable errors.
- [x] Unknown configuration keys fail or warn according to a documented policy.
- [x] Optional future collaboration/scheduling/AI concepts do not create runtime
      services or user-visible placeholders.

## Content safety

- [ ] Existing reference-blog documents can be read and written without losing
      unknown front matter or custom Markdown nodes.
- [x] Unedited files remain byte-identical during discovery.
- [x] Chinese filenames and current resolvable permalinks remain unchanged.
- [ ] Autosave acknowledgement survives browser refresh and service restart.
- [x] Concurrent stale revisions produce a conflict instead of overwriting.
- [ ] Source mode is always available for unsupported visual constructs.

## Asset safety

- [ ] New keys are scoped by immutable document ID.
- [ ] Asset filenames are sanitized and content-addressed.
- [ ] Browser never receives permanent Tencent credentials.
- [ ] MIME type and file content are validated independently of extension.
- [ ] Image processing has size, pixel, memory, and execution limits.
- [ ] Legacy `/static/**` resources cannot be deleted by the application.
- [ ] Orphan deletion is previewed and requires explicit confirmation.

## Preview and publishing

- [ ] Preview uses actual Hexo output and theme.
- [ ] Only one release mutates a workspace/target pair at a time.
- [ ] A failed preflight/build leaves production untouched.
- [ ] Assets upload before referencing HTML.
- [ ] Publish completion awaits and validates every provider operation.
- [ ] A no-op release performs no object uploads.
- [ ] Cache invalidation includes changed HTML, indexes, feeds, and sitemap.
- [ ] Public URL verification confirms the expected release marker.
- [ ] Rollback restores the previous verified release.
- [x] Interrupted jobs recover or terminate deterministically after restart.

## Security

- [ ] HTTPS and trusted reverse-proxy configuration are documented.
- [ ] CSRF, secure-cookie, origin, and session protections are tested.
- [x] Workspace path traversal and symlink escape tests pass.
- [x] Browser-configurable arbitrary shell commands are impossible.
- [x] Adapter subprocesses have timeouts and an allowlisted environment.
- [x] Job logs redact configured secret values and authorization headers.
- [ ] Container runs as non-root with read-only root filesystem where practical.
- [ ] Dependency and container scans have no unaccepted critical finding.

## Performance and reliability

- [ ] Editor shell interactive time is below 1.5 seconds on the home LAN.
- [ ] Non-build API latency is below 200 ms p95 on the reference server.
- [ ] Autosave acknowledgement is below 150 ms p95.
- [ ] Reference-blog build completes successfully from a cold container.
- [ ] Typical changed-article release completes within 90 seconds.
- [ ] Daily backup and tested restore meet 15-minute RTO.
- [ ] Studio downtime has no observable effect on the public blog.

## Product delivery

- [ ] Docker Compose quick start succeeds on a clean machine.
- [ ] Traefik example serves the configured HTTPS hostname.
- [ ] Landing page accurately demonstrates verified capabilities only.
- [ ] Documentation search, navigation, deep links, and mobile layout work.
- [ ] Quick start is completed by someone following only the documentation.
- [ ] Reference blog is usable at `blog-editor.internal.wj2015.com`.
- [ ] Existing public blog URLs and legacy resources remain reachable.
- [ ] v0.1.0 release artifacts, checksums, notes, and upgrade instructions exist.

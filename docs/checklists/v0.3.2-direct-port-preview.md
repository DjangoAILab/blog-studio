# v0.3.2 Direct-Port Development Preview Release Checklist

Every checked item needs an automated result or a reproducible production
observation. Preview validation must not change canonical blog content or
publish any release.

## Product and configuration contract

- [ ] Development profiles distinguish the internal readiness `baseUrl` from
      the browser-facing `previewUrl`.
- [ ] Owner-editable Site YAML still selects only a host-defined profile; it
      cannot set commands, ports, internal URLs or preview URLs.
- [ ] A missing `previewUrl` disables only the open action and gives a precise
      administrator-facing remedy.
- [ ] A ready preview opens its configured `previewUrl` directly, never a
      Studio `/api/sites/.../development/proxy/` URL.

## Runtime and ingress

- [ ] Studio runs the development command only in its per-Site sandbox and
      uses the internal `baseUrl` for readiness checks.
- [ ] The base Compose service declares development ports 4000--4100 for
      container-network use without publishing them on host interfaces.
- [ ] The optional Traefik preview route sends the configured preview hostname
      straight to container port 4000 and does not reach Studio port 4310.
- [ ] The reference Hexo command explicitly listens on the configured
      container interface and port.
- [ ] Stop and restart make the direct origin unavailable and available again
      without modifying canonical source.

## Regression and security

- [ ] The obsolete API content-proxy route and its tests are removed.
- [ ] Unit/API/browser tests cover profile serialization, missing-address UI,
      direct-link UI, sandbox execution, start/restart/stop, and configuration
      rejection.
- [ ] Full formatting, type, unit and browser checks pass.
- [ ] Preview ingress is documented as operator-controlled and private; no
      Studio authentication claim is made for a directly routed preview.

## Production acceptance

- [ ] A prior image and configuration rollback target are recorded before
      deployment.
- [ ] HTTPS editor health and owner login remain healthy after deployment.
- [ ] `https://blog-editor-preview.internal.wj2015.com/` returns Hexo HTML;
      sampled CSS, JavaScript and image requests return their expected media
      types and 200 status.
- [ ] The preview article, a root-relative asset and a root-relative site link
      render correctly in a real browser.
- [ ] Studio stop produces an expected unavailable preview response; restart
      restores the same direct origin and current working-copy content.

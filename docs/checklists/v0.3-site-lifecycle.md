# v0.3 Site Lifecycle Release Checklist

Every checked item must link to a reproducible focused test, browser evidence,
container command, or real-environment observation. Passing a broad test suite
does not substitute for evidence of the listed behavior.

## Safety and migration

- [ ] Existing v0.2 installations start with their current environment-managed
      configuration and no loss of registered Sites, drafts, releases, or
      credentials.
- [ ] Host policy continues to own allowed roots, adapter allowlists, secret
      references, environment allowlists, and command-execution limits.
- [x] Owner-editable Site YAML rejects literal credentials and paths outside
      host policy; every activation is schema-validated and atomically written.
      Evidence: [site configuration and lifecycle](../verification/v0.3-site-configuration-and-lifecycle.md).
- [ ] Failed validation or runtime reload leaves the previous Site configuration
      and active runtime intact.
- [ ] Site configuration activation, revert, pause, unregister, and purge are
      audited with optimistic revision checks. Purge requires re-authentication
      and never removes a repository or publish target.

## Preview, metadata, search, and ordering

- [x] Markdown preview fills its canvas both with and without a fallback banner,
      at desktop and mobile widths. Evidence:
      [preview and ordering](../verification/v0.3-preview-and-ordering.md).
- [x] Front matter preserves unknown fields, field order, comments, quoting,
      and scalar-versus-list form when a normal field is edited.
      Evidence: [front matter](../verification/v0.3-front-matter.md).
- [x] Standard fields and Site-schema custom fields have accessible controls;
      the advanced YAML editor supports every other supported value and reports
      parse locations.
      Evidence: [front matter](../verification/v0.3-front-matter.md).
- [x] Malformed canonical front matter cannot be rewritten by the form and has a
      source-repair workflow.
      Evidence: [front matter](../verification/v0.3-front-matter.md).
- [x] New documents use Site defaults/templates without breaking native Hexo
      drafts and promotion.
      Evidence: [front matter](../verification/v0.3-front-matter.md).
- [x] Content exposes published, content-updated, working-copy, filesystem, and
      activity timestamps with correct fallback semantics. Evidence:
      [preview and ordering](../verification/v0.3-preview-and-ordering.md).
- [x] Default ordering is activity descending; supported fields and directions
      are stable across pages and never use filesystem mtime as content time.
      Evidence: [preview and ordering](../verification/v0.3-preview-and-ordering.md).
- [x] Global search focuses from the top bar and returns debounced results across
      title, path, tags, and categories without Enter. Schema-marked fields are
      added with the Site content-model task. Evidence:
      [global search](../verification/v0.3-global-search.md).
- [ ] URL restoration preserves search, filters, sort, direction, and page.

## Site lifecycle and local development

- [x] The owner can add another trusted Site after the first registration,
      configure it, validate it, pause it, repair it, and unregister it.
      Evidence: [site configuration and lifecycle](../verification/v0.3-site-configuration-and-lifecycle.md).
- [ ] Invalid or paused Sites do not degrade other active Sites.
- [ ] A development process only runs in a per-Site sandbox, never the canonical
      workspace.
- [ ] Development status, bounded logs, start, open, restart, stop, and cleanup
      work across failure, cancellation, process exit, Studio restart, and
      sandbox expiry.
- [ ] A current working-copy revision is automatically synchronized to the local
      Site; a failed hot update produces a truthful stale/restart state.
- [ ] The browser can open the local Site through Studio's same-origin proxy in
      a new tab; the embedded preview is optional and does not weaken CSP or
      authentication boundaries.
- [ ] ChangeSet review reports whether the local Site matches the reviewed
      working-copy and configuration revisions.

## Release closure

- [x] Content ChangeSets freeze the active Site configuration revision and are
      invalidated when that configuration changes. Evidence:
      [site configuration and lifecycle](../verification/v0.3-site-configuration-and-lifecycle.md).
- [ ] Production build commands are distinct from development commands and a
      release only builds an applied, committed ChangeSet.
- [ ] Filesystem targets reject source/data/other-Site overlap, require explicit
      baseline adoption, preserve protected and unmanaged files, and keep a
      durable recovery journal.
- [ ] Filesystem publish, cancellation, interrupted recovery, public-marker
      verification, and rollback have focused automated coverage.

## Release acceptance

- [ ] Focused unit, API, migration, adapter, and browser tests pass.
- [ ] Full `CI=true corepack pnpm check`, formatting, and browser E2E gates pass
      using the repository-declared runtime.
- [ ] A Linux amd64 image passes quick-start, hardened container, operations,
      backup/restore, restart, and rollback smoke tests.
- [ ] `main` contains the complete reviewed change set and is pushed to origin.
- [ ] `internal.wj2015.com` runs the verified image with a pre-deployment backup
      and an available rollback image.
- [ ] Authenticated real-environment acceptance proves reference-site discovery,
      metadata preservation, local preview, search/sort, site management,
      ChangeSet invalidation, and a non-production filesystem release/rollback.

# v0.2 Site-first Release Checklist

Every checked item must link to reproducible evidence: a focused automated
test, command output, screenshot, trace, migration fixture, or real-environment
observation. A feature is not complete when only its happy path works.

## Scope and product model

- [x] `Site` is the user-facing root object in onboarding, navigation, API
      contracts, and settings; `Workspace` appears only in advanced diagnostics.
      Evidence: [Site contract](../verification/v0.2-site-contract.md),
      [first-run guide](../guides/sites-and-first-run.md), and
      [Linux amd64 operations proof](../verification/v0.2-operations.md).
- [x] The release contains no statistics, AI analysis, inactive Agent controls,
      or landing-page claims for unverified future capabilities.
      Evidence: [scope and migration verification](../verification/v0.2-scope-and-migration.md).
- [x] Markdown/site files and Git remain canonical; SQLite operational data can
      be rebuilt or migrated without rewriting canonical content.
      Evidence: [scope and migration verification](../verification/v0.2-scope-and-migration.md).
- [x] Existing v0.1 configuration, drafts, release records, and reference-blog
      content open without loss or an unsafe manual conversion.
      Evidence: [scope and migration verification](../verification/v0.2-scope-and-migration.md).

## Interaction-design gate

- [x] Three materially different visual directions exist for onboarding,
      library, editor/preview, and ChangeSet review on desktop and mobile.
      Evidence: [candidate specification and artifact index](../design/v0.2-interaction-target.md)
      and [selection record](../verification/v0.2-design-selection.md).
- [x] The owner has selected one direction before those production surfaces are
      visually rewritten. Evidence:
      [owner design selection](../verification/v0.2-design-selection.md).
- [x] Semantic color, material, elevation, typography, spacing, radius, focus,
      and motion tokens are documented and represented in code. Evidence:
      [Focused Workbench UI kernel verification](../verification/v0.2-ui-kernel.md).
- [x] Content/diff surfaces remain stable and paper-like; transparency and blur
      are limited to functional navigation, control, sheet, and transient layers.
      Evidence:
      [Focused Workbench UI kernel verification](../verification/v0.2-ui-kernel.md).
- [x] Reduced motion, reduced transparency, increased contrast, keyboard access,
      and non-blur fallbacks have explicit targets and automated/manual evidence.
      Evidence: [Focused Workbench UI kernel verification](../verification/v0.2-ui-kernel.md).

## Owner authentication

- [x] A trusted CLI command reports whether owner credentials are initialized
      without revealing credential material.
- [x] A trusted CLI command initializes the first owner password and rejects
      weak input, non-interactive ambiguity, and accidental replacement.
- [x] No unauthenticated browser visitor can claim first ownership.
- [x] Login accepts the owner password and never displays or requests the legacy
      opaque deployment token in the normal product journey.
- [x] The authenticated owner can change the password after re-authentication.
- [x] A trusted CLI reset rotates credentials and invalidates every existing
      session.
- [x] Password verifiers use a memory-hard KDF, constant-time verification, a
      versioned format, unique salt, and no plaintext or reversible storage.
- [x] Authentication logs, HTTP errors, backups, and support diagnostics redact
      passwords, verifiers, cookies, CSRF values, and legacy tokens.

## Site onboarding and settings

- [x] First run distinguishes “no Site registered”, “credentials not ready”,
      and “configuration invalid” with a safe next action for each state.
      Evidence:
      [first-run state contract](../verification/v0.2-first-run-contract.md).
- [x] Site discovery inspects only administrator-allowed roots and cannot escape
      via paths, symlinks, config references, or subprocess working directories.
      Evidence: [Site contract verification](../verification/v0.2-site-contract.md).
- [x] Discovery previews name, URL, engine, content counts, resource policy,
      repository state, and capability diagnostics before confirmation.
      Evidence: [Site contract verification](../verification/v0.2-site-contract.md).
- [x] Registration creates a durable Site record with display identity separate
      from technical workspace ID. Evidence: [Site contract verification](../verification/v0.2-site-contract.md).
- [x] Settings can inspect and update supported Site metadata with validation,
      conflict handling, audit evidence, and no silent canonical-content edits.
      Evidence: [Site contract and browser verification](../verification/v0.2-site-contract.md).
- [x] The existing `wj2015-blog` configuration migrates or registers through the
      same public Site contract used by a new installation. Evidence:
      [real reference Site verification](../verification/v0.2-reference-site.md).

## Preview

- [x] Every supported document has an immediate, sanitized Markdown preview
      that requires no generator subprocess or provider connectivity. Evidence:
      [preview contract verification](../verification/v0.2-preview-contract.md).
- [x] Generator preview remains available as an enhanced fidelity mode when the
      Site capability supports it. Evidence:
      [preview contract verification](../verification/v0.2-preview-contract.md).
- [x] A generator preview is never marked ready until its actual target returns
      a successful, renderable response containing the expected session marker.
      Evidence: [preview contract verification](../verification/v0.2-preview-contract.md).
- [x] Missing output, broken route, timeout, subprocess failure, and unsupported
      generator states fall back to Markdown with actionable diagnostics.
      Evidence: [preview contract verification](../verification/v0.2-preview-contract.md).
- [x] Preview sandboxes never mutate canonical content and are reclaimed after
      success, failure, expiry, restart, and cancellation. Evidence:
      [preview contract verification](../verification/v0.2-preview-contract.md).
- [x] Preview content and resource URLs enforce traversal, script injection,
      origin, CSP, and untrusted-HTML boundaries. Evidence:
      [preview contract verification](../verification/v0.2-preview-contract.md).

## Generic resources

- [x] The resource model supports policy-controlled non-image attachments while
      preserving the optimized image path. Evidence: [resource contract verification](../verification/v0.2-resource-contract.md).
- [x] Resource policies define allowed MIME types, extensions, byte limits,
      naming, storage scope, and whether inline preview is permitted. Evidence:
      [resource contract verification](../verification/v0.2-resource-contract.md).
- [x] MIME sniffing, extension checks, filename sanitization, immutable keys,
      traversal defense, and upload completion are verified independently.
      Evidence: [resource contract verification](../verification/v0.2-resource-contract.md).
- [x] The editor can link or embed resources according to capability and inserts
      portable Markdown/source syntax rather than engine-specific hidden state.
      Evidence:
      [content workbench verification](../verification/v0.2-content-workbench.md).
- [x] Unsupported or suspicious inputs are explicitly rejected before storage;
      uploading, retryable failure, orphaned, and local/remote stored resources
      have contextual UI states and safe recovery. v0.2 stores nothing in a
      quarantine state. Evidence:
      [resource contract verification](../verification/v0.2-resource-contract.md)
      and [content workbench browser journey](../verification/v0.2-content-workbench.md).
- [x] Legacy `/static/**` resources remain readable and cannot be silently moved,
      rewritten, or deleted. Evidence:
      [real reference Site verification](../verification/v0.2-reference-site.md)
      and [preview contract verification](../verification/v0.2-preview-contract.md).

## Prepare changes and local commit

- [x] `Prepare changes` is the primary low-risk action and does not build,
      upload, invalidate a cache, push Git, or change the public Site. Evidence:
      [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] Preparation freezes exact source, draft, resource, configuration, and
      repository revisions into a durable ChangeSet. Evidence:
      [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] ChangeSet review shows added, modified, deleted, conflicted, ignored, and
      unmanaged files plus document/resource summaries and relevant diffs.
      Evidence:
      [ChangeSet contract and browser verification](../verification/v0.2-change-set-contract.md).
- [x] Re-preparing identical inputs is idempotent; changed inputs invalidate or
      supersede stale review rather than silently altering it. Evidence:
      [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] Applying a ChangeSet is optimistic and atomic enough to avoid partial
      canonical edits; interruption has deterministic recovery evidence.
      Evidence: [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] Local Git commit is a separate confirmed action with editable message,
      exact staged-file review, clean failure recovery, and recorded commit ID.
      Evidence: [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] Unrelated or pre-existing working-tree changes are never silently staged,
      reverted, committed, or published. Evidence:
      [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).

## Remote release

- [x] Remote release is visually and operationally distinct from preparation
      and local commit, with target, effect, revision, and rollback information.
      Evidence:
      [ChangeSet contract and browser verification](../verification/v0.2-change-set-contract.md).
- [x] A remote release can only use an immutable reviewed revision/ChangeSet and
      never whichever files happen to exist at click time. Evidence:
      [ChangeSet contract and browser verification](../verification/v0.2-change-set-contract.md).
- [x] Existing preflight, serialization, provider-await, verification,
      cancellation, recovery, and rollback guarantees remain green. Evidence:
      [ChangeSet contract and browser verification](../verification/v0.2-change-set-contract.md).
- [x] A reference journey proves prepare -> review -> local commit without any
      provider mutation, followed by a separately confirmed staging release.
      Evidence: [ChangeSet contract verification](../verification/v0.2-change-set-contract.md).
- [x] No production blog release is initiated during v0.2 verification without
      an explicit, contemporaneous owner confirmation. Evidence: the
      [ChangeSet browser journey](../verification/v0.2-change-set-contract.md)
      uses an auto-deleted local fixture and `example.invalid` only.

- [x] Unit, contract, integration, browser, migration, security, accessibility,
      type, lint, format, build, container, quick-start, and operations suites pass.
      Evidence: [release-candidate index](../verification/v0.2-release-candidate.md)
      and [container/operations verification](../verification/v0.2-operations.md).
- [x] Critical first-run, login/reset, published edit, preview fallback,
      ChangeSet, commit, and release failures are covered by browser evidence.
      Evidence: [content workbench](../verification/v0.2-content-workbench.md),
      [ChangeSet contract](../verification/v0.2-change-set-contract.md), and
      [owner authentication](../verification/v0.2-owner-auth.md).
- [x] Non-build API and autosave latency do not regress beyond the documented
      v0.1 budgets; blur/motion do not violate the selected frame/performance budget.
      Evidence: [performance verification](../verification/v0.2-performance.md).
- [x] Backup, restore, cold restart, credential reset, migration rollback, and
      release rollback are exercised against a disposable production-like fixture.
      Evidence: [container/operations verification](../verification/v0.2-operations.md).
- [x] Home-server upgrade preserves public-blog availability and passes health,
      authentication, reference-content, preview, and rollback smoke checks.
      Evidence:
      [home-server candidate](../verification/v0.2-home-server-candidate.md).
- [x] The owner was informed that the current credential appeared in an
      acceptance-task tool log and explicitly accepted continued use without
      rotation on 2026-08-06. The credential file remains outside the repository
      with mode `0600`. This records owner risk acceptance, not credential
      rotation or remediation.
- [x] Release notes, operator upgrade steps, CLI reference, user journey docs,
      and an evidence index describe only verified behavior. Evidence:
      [v0.2 release notes](../releases/v0.2.0.md),
      [upgrade guide](../guides/upgrading.md), and
      [release-candidate index](../verification/v0.2-release-candidate.md).
